# AGENTS.md

Package: @ecx/glfw

FFI bindings to GLFW 3.4, plus the vendored native library. Windowing,
monitor, input (keyboard/mouse/joystick/gamepad), and OpenGL/Vulkan context
management -- no C compiler or system GLFW needed.

## Layout

- `config.toml` - Cloud package configuration (`@ecx/glfw`).
- `src/glfw.ins` - the bindings module (`import ecx::glfw`). Generated by
  insbind from `GLFW/glfw3.h` with `-DGLFW_INCLUDE_NONE`; do not hand-edit.
- `src/window.ins` - the idiomatic RAII wrapper (`import ecx::glfw::window`):
  refcounted `window.init()/terminate()`, self-destroying `window.Window`,
  `window.create/create_hidden/poll/wait_events`. Hand-maintained.
- `bin/<target>/` - vendored binaries. Currently
  `bin/x86_64_windows/glfw3.dll` (MSVC `/MT`; no VC++ runtime dependency).

Prefer the wrapper for application code; drop to the raw module for anything
it does not cover.

## Conventions (from insbind, mirroring windows::*/unix::*)

- Opaque handles are `u64`: `GLFWwindow*`, `GLFWmonitor*`, `GLFWcursor*`.
  So are function pointers (`GLFWglproc`) and every `GLFW*fun` callback
  typedef.
- C strings are `text` (const) or `u8*` (mutable).
- Constants are zero-argument functions: `glfw.glfw_visible()`,
  `glfw.glfw_key_escape()`, `glfw.glfw_not_initialized()`, ... (hundreds of
  them -- key codes, button/hat/joystick codes, window-hint names and values).
- Callbacks into Insty work: pass `cast<u64>(&my_fn)` to the
  `glfwSet*Callback(u64)` functions; the Insty function is invoked from C
  (keep its signature C-compatible, see the consumer demo).

## Regenerating the bindings

```bash
insbind bind GLFW/glfw3.h -I include -I <insbind>/include \
    -DGLFW_INCLUDE_NONE --module glfw --dll glfw3.dll --abi-check > src/glfw.ins
```

`--abi-check` emits `glfw.abicheck.ins`; compile + run it with `insty` to
verify `GLFWvidmode`/`GLFWimage`/`GLFWgamepadstate` layouts. Regenerate when
bumping the vendored GLFW version (and match `[project].version`).
