# AGENTS.md

Package: @ecx/zlib

FFI bindings to zlib 1.3.1, plus the vendored native library. Consumption
needs no C compiler, no system zlib, and nothing installed beyond `cloud`.

## Layout

- `config.toml` - Cloud package configuration (`@ecx/zlib`).
- `src/zlib.ins` - the bindings module (`import ecx::zlib`). Generated by
  insbind from the real `zlib.h`; do not hand-edit - regenerate instead
  (see below).
- `bin/<target>/` - vendored native binaries per target. `cloud build`
  stages the active target's files next to the consumer's executable.
  Currently: `bin/x86_64_windows/zlib1.dll` (built from the official
  zlib-1.3.1 sources with MSVC `/MT`; no VC++ runtime dependency).

## Conventions (from insbind, mirroring windows::*/unix::*)

- Opaque handles and function pointers are `u64` (e.g. `state`, `zalloc`).
- C strings are `text` (const) or `u8*` (mutable). Built with `-DZLIB_CONST`,
  so `z_const` is const: `msg` is `text`.
- Constants are zero-argument functions: `zlib.z_ok()`, `zlib.z_stream_end()`.
- Variadic functions (e.g. `gzprintf`) and extern globals are skipped by
  design (shim territory); `static inline` is not linkable and also skipped.

## Regenerating the bindings

From the zlib-1.3.1 source tree (zlib.h + zconf.h present):

```bash
insbind bind zlib.h -I . -I <insbind>/include -DZLIB_CONST \
    --module zlib --dll zlib1.dll --abi-check > src/zlib.ins
```

`--abi-check` writes `zlib.abicheck.ins` next to the bindings: compile and
run it with `insty` to verify struct layouts against the target ABI. Re-run
this when bumping the vendored zlib version (and bump `[project].version`
to match upstream).

## ABI notes

- Built for `x86_64_windows` (LLP64): `uLong` -> `u32`, `z_off_t` -> `i32`,
  `z_off64_t` -> `i64`. A Linux (`LP64`) variant of the bindings needs a
  separate generation pass with `--target x86_64_linux`; the convention is
  one bindings file per data model only when they differ (they do for
  `long`-typed APIs like gzseek) -- resolve when the first Linux binary
  lands in `bin/`.
